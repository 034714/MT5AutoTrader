MT5AutoTrader 使用说明
========================

零、界面速览（2026-09 更新）
----------------------------
- 「图表分析」页 = 实时K线（关键位/止损止盈拖拽）+ 手动下单 + 实时持仓 + 挂单，一页看盘下单；
  右键点K线任意位置可按所指价位快速市价下单（确认后发单）。
- 图表下单：右键可挂「限价/条件单」（到价市价进场，软件自动判断类型）；挂单草稿在图上
  拖动蓝（开仓）/红（止损）/绿（止盈）三条线，拖开仓价时止损止盈保持距离跟着走；
  持仓开仓价线拖动 = 止损止盈整组平移；挂单线拖动 = 改触发价；止盈线拖动可填平仓手数
  （到价只平一部分，剩余继续持有）。
- 总览只保留账户/Runner/信号/持仓/最近动作；持仓表带「已实现盈亏」（部分平仓落袋的部分）。
- 历史成交可选「本软件成交 / 账户全部成交」，顶部是复盘统计卡片；部分平仓的仓位
  归入「持仓中的建仓记录」（显示剩余手数和已实现盈亏），全部平仓后才计入已平仓交易。
  账户净值走势为整行大图：蓝线=余额（成交流水反推，MT5 不保存历史净值）、
  绿线=净值（页面开着时每分钟采样，含浮动盈亏），末点数值同色标注。
- 风控参数的阶梯保本按百分比填写（1 = 1%），保存时自动按浮盈从小到大排序；
  推荐起手 1/0、2/1、3/2、4/3。
- 「外观」页可换背景图片（本地浏览器保存，不上传）、调背景变暗、开玻璃质感
  （模糊强度可调）、工具条选上方或左侧；左侧为通天整条，可收起成窄条。
- 训练页：正数步数 = 本次新增步数（续训填 60 就是起点再加 60）；单引擎默认每
  10 步存检查点，同品种同周期标签保留最近 2 个，正常结束/早停/响应停止也存最终进度。
  「停止训练」先请求保存退出，超时 40 秒会强杀，不能保证强杀后的最后进度已保存。
  「查看/选择续训检查点」可选择或删除；岛中断保存各岛实际进度，有冠军时会按
  冠军实际已完成步数导出普通检查点，切回单引擎仍须通过上下文校验。
- 日志页可选「训练日志（最近一次）」。
- 训练产物按 品种+周期 命名（best_BTCUSD__H1.json 等），不同周期互不覆盖；
  旧命名文件仍可正常加载和绑定。

一、快速开始
------------
1. 打开 MT5 终端并登录你要交易的账号（真实下单前还要点亮 MT5 工具栏的"算法交易"按钮）。
2. 双击 start.bat。
3. 浏览器打开 http://127.0.0.1:8900。重复双击不会多开，只会打开已有页面。
4. 停止：双击 stop.bat（会先让交易 Runner 安全退出，再关看板）。
5. 进程环境变量 MT5AUTOTRADER_OFFLINE=1 可离线查看网页/本地文件训练，不连接 MT5，
   不能启动 Runner 或 direct-MT5 训练；不改用户配置。不继承此变量，正常用 start.bat
   重启即可恢复默认模式。此模式不是 dry-run，也不验证真实成交。

二、训练数据在哪里（Parquet 说明）
----------------------------------
「从 MT5 获取并训练」会自动把 K 线保存到数据目录：

    D:\K线数据\

文件名规则是  品种_周期.parquet（M5/M15/M30/H1/H4/D1 可选，以下用 H1 举例）。
注意品种名自带下划线时会出现双下划线，这是正常的：

    ETHUSD_  →  ETHUSD__H1.parquet
    BTCUSD_  →  BTCUSD__H1.parquet
    XAUUSD   →  XAUUSD_H1.parquet

这些文件是训练的"原料"，也可以用于回测。数据目录可以在 trader_config.json 的
kline_cache_dir 里修改。你不需要手工制作或理解 Parquet 文件。

三、续训：接着上次的训练成果继续
--------------------------------
支持续训，但必须区分“同上下文恢复”和“换数据继续搜索”：

1. 单引擎检查点在 checkpoints\ckpt_品种_周期_step_数字.pt；岛模式为
   island_ckpt_品种_周期_step_数字.pt。未勾选“从头训练”时，按数字步数选最新点，
   或使用手动选择的检查点；不同周期互不覆盖。
2. 正数步数是“本次新增步数”：已有 60 步，再填 60，目标就是 120。
   命令行 train_file.py / train_island.py 的 --steps N 同样如此；未指定或为 0 时
   沿用默认总目标，不表示新增 0 步。岛模式目标按每岛计算。
3. 检查点 training_context 记录品种、周期、数据内容指纹，以及评分、特征、
   归一化、词表版本和评估参数。同上下文恢复模型、优化器、候选池、曲线、
   停滞状态和随机数状态；品种/周期不符会拒绝加载。缺少身份上下文的旧检查点
   不能用于文件续训，缺少或不匹配的词表版本也不能硬接，需明确从头训练。
4. 刷新同品种同周期数据或更改评估上下文后，检查点只作 hotstart：保留模型、
   优化器和已完成步数，清空旧冠军分数/公式、候选池、奖励基线和曲线，并重置
   相关停滞/早停状态。旧分数不能作为新数据上的下限。
5. 检查点 step 是实际完成的更新数（completed_steps），不是计划目标，也不是
   曲线的零基 step。单引擎默认每 10 步保存、同标签保留最近 2 个；正常结束、
   早停或响应 TRAIN_STOP 后还会存最终进度，短训练不必等到周期保存节点。
6. 岛中断点的顶层 step 是阶段起点，phase_interrupted 标记中断，每岛各存真实
   已完成步数；续训跳过已完成更新。岛数、迁移间隔和迁移 Top-K 必须匹配。
   有有效冠军时，按冠军实际完成步数导出普通检查点供单引擎恢复。
7. “停止训练”写 TRAIN_STOP 并最多等待 40 秒退出，超时则强杀。正常处理停止时
   会保存检查点和曲线，策略须有有效有限分数冠军且通过保护条件才保存；强杀、
   崩溃、磁盘满或权限错误不能保证保存最后进度。产物用同目录临时文件 +
   os.replace 替换，不承诺断电持久性。
8. “从头训练”只清理对应模式、品种/周期的检查点和曲线，不自动删除已有策略。
   同完整上下文且评分/特征版本一致时，只用更高的有限分数覆盖旧策略；旧口径、
   不同上下文或无效旧文件受保护。换数据或升级后看到新训练结果，并不代表磁盘
   策略已更新；发布前先备份、明确处理旧策略文件，并核对要绑定的实际内容。
9. Runner 只对已绑定策略文件的实际变化进行热更新，不自动绑定新策略，也不会
   把受保护未更新的文件变成新策略。
10. 训练曲线只写入并读取 training_history\，普通曲线为
    training_history_品种_周期.json，岛汇总增加 _island，单岛增加 __islN。
    根目录旧 training_history*.json 不兼容，不自动迁移，放在根目录不会显示。
11. 训练固定使用 CPU，不提供显卡加速开关，无需安装 GPU 相关包。

训练评分、策略语义与快速回测
----------------------------
- 新训练使用 causal-features-v2 特征、causal-portfolio-v3 评分和
  causal-prefix-rolling500-v2 归一化。单品种前 499 根输出中性，第 500 根起
  使用因果前缀常量判断与 500 根滚动归一化；多品种用同一时刻截面，不看未来。
- 旧策略缺少 feature_semantics_version 时按 legacy-v1 部署，保留旧特征及
  归一化。旧全局常量判断不是因果，不用于新训练/快速回测。未知语义版本拒绝，
  词表须兼容；旧文件名可加载不代表旧检查点或旧评分可直接继承。
- 训练分数是“连续敞口 × 目标对数收益 − 换手成本”的 proxy，用于排序，不是
  固定手数 Bid/Ask 盈亏或账户货币收益。验证段用于选冠军，仍需未参与搜索的
  独立样本外检验，不能把高分当作实盘盈利证明。
- 网页快速回测只读 MT5 已收盘历史，固定手数、单仓位，收盘信号下一根开盘成交，
  最后一根已收盘 K 线收盘强制平仓。Bid K 线 + 历史 bar spread 近似 Ask，
  不是逐笔真实 Bid/Ask；滑点和每手单边佣金为用户假设，默认 0，不计库存费。
- 盈亏用 order_calc_profit 按当前合约/汇率换算账户货币，不是历史汇率成交收益。
  回撤按逐 bar 收盘可平仓净权益（含浮盈亏和预计平仓成本），不含 bar 内极值。
  不模拟实盘 SL/TP、阶梯止损、S/R、部分止盈、完整风控、保证金、资金限制、
  流动性或成交失败；不会发订单、启动 Runner 或写入回测产物。
- 快速回测始终用新版因果特征和归一化，即便原策略是 legacy-v1，也可能与其
  部署信号不同。它与训练 proxy、离线回测报告、真实成交记录是不同口径，
  不应直接互相当作验证结果；有限预热与实盘滚动窗口也可能带来信号差异。

四、目录与文件说明
------------------
主目录只保留你要用的东西；所有代码都在 src\ 里，平时不用碰。

【主目录】
  start.bat                正式启动入口（双击这个）
  stop.bat                 正式停止入口（双击这个）
  说明.txt / README.md     使用说明
  AGENTS.md                给后续 AI 的交接规则（已知的 Windows 坑都记在里面）
  trader_config.json       看板保存的全部配置：dry-run 开关、策略绑定、手数、
                           风控参数（含支撑/阻力优化）、数据目录。删掉会自动重建默认。
  trader_config.example.json  配置模板（开源仓库用，本机不用管）
  fallback_python.txt      本机过渡期的 Python 路径兜底（不入库；有了 .venv 后可删）
  requirements.txt         Python 依赖清单
  .env.example             环境变量模板。MT5 凭证留空也能用（依赖终端已登录）

【运行数据（重要）】
  strategies\              策略库。best_品种_周期.json；受旧策略保护时不会覆盖。
  checkpoints\             带训练上下文和实际已完成步数的续训检查点。
  training_history\        训练曲线唯一目录；不读取根目录旧曲线文件。
  portfolio_state.json     本地持仓台账（重要！有真实持仓时千万别删）。
  logs\                    日志与 Runner 状态。
  backtest_output\         回测报告输出。

【代码（在 src\ 里，平时不用碰）】
  src\app.py               FastAPI 看板服务（端口 8900）
  src\web\index.html       看板页面
  src\trading\             交易引擎：mt5_client / signal_engine / risk / runner / history
                           sr.py + srlab\ 为支撑/阻力位引擎（开仓止盈止损优化）
  src\model_core\          训练引擎（特征、算子、公式虚拟机）
  src\data_pipeline\       数据加载与 MT5 分块拉取
  src\train_file.py        训练主程序（看板后台调用）
  src\mt5_train.py         "从 MT5 获取并训练"入口（周期可选）
  src\train_island.py      岛模式训练程序（多种群探索 + 精英迁移）
  src\run_backtest.py      回测主程序
  src\tests\               按领域组织的单元测试与契约测试
  scripts\stop_all.ps1     stop.bat 背后的实际停止逻辑，不需要手动碰

【可以放心删的】
  __pycache__\ 文件夹      Python 缓存，删了自动重建
  logs\ 里按时间戳命名的旧日志

【不要删的】
  portfolio_state.json     有真实持仓时删了会导致状态错乱
  checkpoints\             删了无法续训
  trader_config.json       你的绑定和风控设置
  AGENTS.md                给后续 AI 的交接规则

五、先 dry-run，再真实
----------------------
1. 默认 dry-run：信号照算、动作只记日志，不发真实订单。
2. "交易控制"页启动 Runner，在"总览"看信号和持仓，"日志"页看细节。
3. 每 5~10 秒检查价格风控；只有策略所用周期出现新的已收盘 K 线才重新计算信号。
4. 同方向信号不重复开仓；反向信号先平旧仓、确认成功才开反向仓；平仓失败不开新仓。
5. 风控默认：初始止损 -2%；浮盈 1% 止损到成本；2% 锁 1%；3% 锁 2%；4% 锁 3%。
6. 支撑/阻力优化（风控页可开关）：开仓时自动识别附近的支撑带/压力带
   （V3 融合算法：成交量分布 + 极值结构 + ATR 归一化），止损尽量藏在结构位
   外侧、止盈放在对面关键位之前；固定止损 -2% 始终保留，最终取两者中更保守
   （离开仓价更近）的一个。没有合适的关键位时自动退回固定止损。
7. 关键位前"止盈一半"（风控页可开关）：价格到达对面关键位前，先平掉一半仓位
   锁定利润，剩余仓位继续持有（交给阶梯保本和更远的关键位管理）；可以勾选
   "由模型把关"——只有该关键位的模型守住概率 ≥55% 才执行，弱位可能直接突破
   就不止盈一半。全部止盈会顺延到更远的关键位。手数太小无法拆半（如 0.01 手）
   时自动跳过，不影响持仓。
8. 「总览」页有实时 K 线图：K 线 + 支撑/压力带 + 你的开仓价/止损/止盈/止盈一半
   线，滚轮缩放、拖动平移、双击复位，鼠标悬停看单根 K 线明细。
   止损/止盈/止盈一半三条线都可以按住上下拖动，松手后弹出确认框，框里还能
   直接输入精确价格（到价平仓还能指定手数），点"确认执行"才真正生效。
   图上也会画出最近 7 天的历史成交（▲多/▼空入场，圆点离场：绿=盈利红=亏损）。
   品种框可以输入或下拉选择 MT5 终端里的全部品种（没开仓的品种也能看图）。

六、切换真实下单
----------------
0. 在 MT5 终端点亮工具栏的"算法交易 / AutoTrading"按钮。没点亮时 MT5 拒绝一切
   程序订单（日志出现 retcode=10027），看板顶部会显示"MT5 算法交易未开启"。
1. "交易控制"页点击"请求切换为真实下单"。
2. 弹窗里核对当前服务器、账号、账户货币，再点“确认执行”。请求须携带布尔
   confirmed=true 和新鲜 account_key=[server, login, currency]（login 为整数）；
   后端核对当前账户，账户已切换须重新确认。只点第一步不会切换。
3. 切换后停止并重启 Runner 生效。"立即回到 dry-run"不需要确认，随时可回退。

真实下单前建议确认：策略已回测、手数和止损设置正确、你清楚当前登录的账号。
特别提醒：把 ETH 数据训练的策略绑到 BTCUSD_ 等其他品种属于跨品种使用，效果
没有保证，建议每个品种用各自的数据训练专属策略。

手动下单、平仓、挂单修改/撤销、止损止盈/分批止盈设置也要求 confirmed=true 和
当前 account_key；手动确认操作可以独立于 Runner 的 dry-run 作用于真实 MT5。
order_check / 挂单 check_only=true 仅检查参数，不需要执行确认但仍核对账户，
检查通过不是成交。账户键是软件检查，不是身份认证，也不保证券商端原子执行。

七、故障排查
------------
- 双击 bat 报错：用 start.bat / stop.bat；不要把 PowerShell 长代码写进 bat。
- 任务管理器里看到"两组 python.exe"是正常的：每个程序都是"启动器+真身"两个
  进程（看板一组、Runner 一组）。双击 start.bat 只启动看板这一组；Runner 要在
  "交易控制"页点启动，启动后就会变成两组。stop.bat 会把两组都停干净。
- stop.bat 停止要几秒到十来秒是正常的：它会先给 Runner 发停止信号、等它把
  持仓台账安全写完，再关闭看板（最长等 5 秒），比直接杀进程更安全。
- 页面打不开：再点一次 start.bat；仍失败看 logs\dashboard.log。
- MT5 未连接：手动打开 MT5 终端并登录后刷新网页。
- retcode=10027：MT5 的"算法交易"没点亮。
- retcode=10030：填充模式问题，软件已按品种自动选择，仍出现请反馈日志。
- 模式切换后没生效：确认弹窗点了"确认执行"，且重启了 Runner。
- 训练列表为空：点"只获取并保存"，或确认数据目录里有 .parquet 文件。

八、换 MT5 账户 / 换经纪商会怎样？
----------------------------------
1. 换账户前先停止 Runner。持仓、历史成交和品种列表读取当前 MT5 账户，但实盘
   Runner 不会自动接管另一账户：台账 account_identity=[server, login, currency]
   与当前账户不符时停止本轮真实动作；账户身份不可用时暂停真实动作。
2. 切换后刷新网页，核对服务器/账号/货币、持仓和挂单、策略绑定、手数及合约规格。
   旧账户台账不会因重启自动归属新账户；非空且缺少账户归属的旧实盘台账也需
   人工核对。先备份并明确处理旧状态，再重启；不要为绕过保护直接删除台账。
   止损/分批止盈覆盖也按 account_key 隔离，不接收无账户键或跨账户的旧覆盖。
3. 经纪商品种名可能变化（ETHUSD_ / ETHUSD / ETHUSD.r），需重新核对绑定。
   即便名称相同，报价历史、点差、合约和换汇规则也可能不同，不能认为旧策略、
   缓存数据或回测结果已经适用于新账户。建议重新获取数据并独立回测。
4. MT5 Python 接口一次只连一个终端。本客户端连接当前终端登录账户；换终端后
   重新核对页面账户身份，不依赖 .env 中的 MT5 凭证自动选中目标账户。
5. 每次真实操作重新确认当前 account_key；确认弹窗后账户切换或确认过期时，
   刷新并重新确认。回测、dry-run、mock 测试均不是实际成交验证或盈利保证。
